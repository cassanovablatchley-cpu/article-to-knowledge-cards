# 生成知识卡片

把文章中的关键知识整理成便于复习和自测的卡片。默认输出 5–8 张；原文不足以支持这么多独立知识点时，少输出并说明原因。

## 适用范围

- 接受用户直接粘贴的文章，以及本地 Markdown（`.md`）或纯文本（`.txt`）文件。
- 不支持网页抓取、PDF、其他文件格式、Anki 导出或图形界面。遇到这些请求时，不要尝试绕过限制；简要说明当前范围，并请用户粘贴正文或提供 `.md`/`.txt` 文件。
- 对本地文件，先读取完整内容再提炼。文件无法读取或内容被截断时，不要假装已经理解全文；请用户提供可读取的文本。
- 默认使用原文语言输出；用户明确要求其他语言时再切换。

## 提炼知识

先在内部整理候选知识点，再选卡。优先保留以下内容：

- 定义、核心结论和可复用的规律。
- 因果关系、关键机制、成立条件和边界。
- 容易混淆的概念及二者的区别。
- 决策依据、操作原则，以及原文用证据支持的步骤。
- 原文重点解释、反复强调或用于纠正误解的内容。

把具体人名、故事细节、背景铺陈和只为说明观点服务的例子视为支撑材料，通常不单独成卡。观点类文章要保留“作者主张”和“论证依据”的边界，不把个人判断改写成普遍事实；作者自述的内部观察或试验也要保留其证据范围，不能提升为普遍规律。

每张卡只能围绕一个独立知识点，标题要直接指向这个知识点。删除换一种说法重复出现的结论。同一命题的解释、条件和支撑细节应合并进同一张卡；能够独立理解或复用的不同机制、步骤和适用边界应分别成卡。不能为了增加数量而拆成表面不同、内容相近的卡片，也不能把多个知识点挤进一张卡。

候选知识点多于 8 个时，按对理解主题的重要性排序，合并同一机制下的细节，保留最能构成完整知识骨架的内容。候选不足 5 个时，只生成有依据的卡片，不补写常识、背景、案例或建议。

## 编写卡片

每张卡使用以下结构：

```markdown
### 1. 卡片标题

**核心知识：** 用一句完整的话陈述一个知识点。

**简明解释：** 用 2–3 句话说明它为什么成立、如何理解，或需要满足什么条件。

**例子：** 使用原文中的具体例子；只做压缩和改写，不添加原文没有的细节。
```

`例子` 与 `自测` 二选一：

- 原文有合适的具体案例时，写 `**例子：**`。
- 原文没有案例，或知识点更适合回忆时，写 `**自测：**`，并在下一行用 `答案：` 给出仅依据原文即可得出的答案。

自测题必须能用卡片内容或原文回答，不能依赖额外背景知识。

## 准确性与输出

只使用原文明确给出的事实、数字、关系、条件和结论。允许压缩、改写和梳理逻辑，不允许补充原文之外的事实、数据、因果、例子、建议或延伸阅读。原文没有说清的，不替作者补全。

直接输出卡片，不展示分析过程或候选清单。不要添加总览、金句、行动建议、延伸问题或重复摘抄。若少于 5 张，在卡片前用一句话说明：

```markdown
> 说明：原文仅支持形成 3 个独立的重要知识点，因此未补足到 5 张。
```

若原文几乎只有叙事、情绪或零散信息，无法形成有解释价值的知识卡，简短说明原因并停止。

输出前在内部检查：

- 每张卡的标题、核心知识、解释和例子或自测是否彼此一致。
- 每条事实是否能在原文中找到依据。
- 不同卡片之间是否在讲同一个知识点。
- 卡片数量是否为 5–8 张；若不是，是否确实源于原文信息不足。
